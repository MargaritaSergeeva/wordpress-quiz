# WordPress Quiz

Тестовое задание WordPress / AI Developer: переиспользуемый квиз с передачей заявок и ответов в CRM.

## Текущее состояние

Подготовлены локальное WordPress-окружение, установка через WP-CLI и каркас плагина.
Сам квиз, CRM-приёмник и аудит ещё не реализованы.

Публичный адрес проекта: https://test-wordpress-quiz.duckdns.org
До отдельного развёртывания WordPress там находится временная страница.

## Локальный запуск

Требуются Docker с Compose, Python 3 и Make. Команды выполняются из корня репозитория:

```sh
make install
```

Команда создаст `.env` со случайными паролями, запустит базу и WordPress,
установит сайт и активирует каркас плагина. Повторный запуск сохраняет существующие
данные и учётную запись администратора.

- Сайт: http://localhost:8088
- Админка: http://localhost:8088/wp-admin/
- Логин и пароль: `WP_ADMIN_USER` и `WP_ADMIN_PASSWORD` в локальном `.env`.

Чтобы изменить порт до первого запуска, выполните `make init`, затем измените
одновременно `WP_PORT` и `WP_URL` в `.env`.

```sh
make lint      # Проверка синтаксиса PHP
make logs      # Журналы контейнеров
make down      # Остановка с сохранением данных
```

`docker compose down -v` удаляет базу и файлы WordPress из Docker volumes;
не используйте его для обычной остановки.

## Стек и структура

- WordPress 7.1.0, PHP 8.3, MariaDB 11.4, WP-CLI 2.12.0.
- `compose.yaml` — локальная среда на официальных Docker-образах.
- `wp-content/plugins/wordpress-quiz/` — код собственного плагина.
- `scripts/` — генерация локальной конфигурации и установка WordPress.
- `docs/plan.md` — границы реализации и этапы по ТЗ.

Ядро WordPress, стандартные темы и база находятся в Docker volumes; в Git хранится
наш код и конфигурация для воспроизводимого запуска. Версии PHP и MariaDB ограничены
ветками обновлений; перед сдачей следует зафиксировать использованные digest образов.

## Безопасность и развёртывание

Это **локальная** конфигурация: HTTP-порт привязан к `127.0.0.1`, порт базы наружу
не опубликован. `.env`, дампы, журналы и секреты исключены из Git.
Пример `.env.example` не содержит действующих паролей.

Продакшен-развёртывание потребует отдельной конфигурации: окружение production,
собственные секреты, HTTPS через Nginx и проверка восстановления данных.
Локальную учётную запись администратора не переносить на публичный сайт.
