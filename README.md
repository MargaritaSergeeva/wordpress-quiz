# WordPress Quiz

Переиспользуемый квиз для тестового задания WordPress / AI Developer.
Собственный плагин WordPress с редактором вопросов, блоком Gutenberg и шорткодом,
пошаговой формой и передачей контактов вместе с ответами в тестовую CRM.
Текущая версия плагина — **0.2.6**.

## Ссылки для проверки

- [Демонстрация квиза](https://test-wordpress-quiz.duckdns.org/).
- [Два независимых квиза на одной странице](https://test-wordpress-quiz.duckdns.org/two-quizzes/).
- [Админка WordPress](https://test-wordpress-quiz.duckdns.org/wp-admin/).
- [Ответы на тестовое задание и технический аудит](https://docs.google.com/document/d/1gjr8nYl24ugPvwt5QchkySlBU1VtCjSzrVOrKQxz7TE/edit).

Для проверяющего подготовлена отдельная учётная запись администратора.
Логин и пароль передаются отдельно и не публикуются в репозитории.
Используйте только вымышленные контакты, например `review@example.test`.

## Возможности

- Создание квизов в русскоязычной админке: от 1 до 30 вопросов,
  от 2 до 20 вариантов в каждом, один ответ на вопрос. Можно менять порядок вопросов.
- Размещение на страницах через блок **Квиз** или `[wordpress_quiz id="123"]`.
  Несколько одинаковых или разных квизов работают независимо на одной странице.
- Пошаговое прохождение с возвратом назад и сохранением выбора в открытой форме.
- Обязательные имя, email и согласие. Телефон необязателен: маска автоматически
  добавляет `+7`, принимает вставку с `8`, проверяет российский формат в браузере
  и на сервере. В CRM номер передаётся в виде `+79991234567`.
  Существование и принадлежность номера не проверяются.
- Сохранение контактов и снимка всех вопросов и ответов в WordPress до отправки в CRM.
  Редактирование квиза не меняет ранее полученные заявки.
- Защита от дублей при повторе одного запроса, статусы доставки и ручной повтор.
- Таблица данных, прочитанных непосредственно из тестовой CRM.
- Адаптивная демонстрационная тема и мобильное меню.

## Как проверить

1. Пройдите квиз. Попробуйте перейти дальше без выбора и вернуться назад:
   форма должна показать ошибку или восстановить выбранный ответ соответственно.
2. На шаге контактов проверьте обязательные поля и неполный телефон.
   Отправьте форму с вымышленными данными и согласием.
3. Откройте **Квизы → Заявки**: сверьте контакты, вопросы и ответы,
   статус доставки, количество попыток и CRM ID.
4. Откройте **Квизы → Тестовая CRM** и нажмите **Обновить таблицу**.
   Сверьте полученную запись. Здесь показаны последние 100 записей непосредственно
   из CRM, а не копия таблицы WordPress. Оба раздела доступны администратору.
5. На странице с двумя квизами проверьте независимость их шагов и ответов.
6. В **Квизы → Добавить квиз** задайте название, вопросы и варианты, опубликуйте.
   Создайте страницу, добавьте блок **Квиз** и выберите созданный квиз.
   Альтернатива — шорткод с ID нужной записи.

Сообщение «Заявка получена» означает, что данные сохранены в WordPress.
Статус **Доставлена** появляется только после успешного ответа CRM с ID записи.
Если CRM недоступна, заявка сохраняется со статусом **Ошибка доставки**.
В разделе **Квизы → Заявки**, в столбце **CRM**, у недоставленных заявок есть
кнопка **Повторить доставку**. У доставленных заявок она скрыта; в разделе
**Тестовая CRM** этой кнопки нет. Активная отправка защищена от параллельного повтора;
зависшую попытку можно повторить через 5 минут.

## Локальный запуск

Нужны Git, запущенный Docker с Docker Compose, Python 3 и Make.

```sh
git clone https://github.com/MargaritaSergeeva/wordpress-quiz.git
cd wordpress-quiz
make demo
```

Команда создаёт локальный `.env` со случайными секретами, запускает контейнеры,
устанавливает WordPress на русском языке, активирует плагин и демонстрационную тему,
создаёт примеры квизов и страницы. Существующие демонстрационные квизы сохраняются.
Это команда для локальной среды.

- Сайт: [localhost:8088](http://localhost:8088/).
- Два квиза: [localhost:8088/two-quizzes/](http://localhost:8088/two-quizzes/).
- Админка: [localhost:8088/wp-admin/](http://localhost:8088/wp-admin/).

Локальные доступы находятся в `WP_ADMIN_USER` и `WP_ADMIN_PASSWORD` файла `.env`.
Они не являются доступами к публичному сайту. `.env` исключён из Git.

Для остановки используйте `make down`, для повторного запуска — `make up`.
Остановка сохраняет данные в Docker volumes. `docker compose down -v` удаляет их.

## Проверки и сборка плагина

При запущенной локальной среде:

```sh
make lint
python3 tests/integration.py
python3 tests/crm-view.py
```

Интеграционный тест проверяет сохранение и доставку полного набора ответов,
валидацию контактов, нормализацию телефона, защиту от дублей и поведение при сбое CRM.
Он временно останавливает **локальную** CRM, затем запускает её и проверяет повтор доставки.
Тест просмотра CRM запускайте после интеграционного: ему нужна хотя бы одна заявка.
Он проверяет авторизацию, отображение полученных записей, ошибки и пустое состояние.
Оба теста предназначены для localhost и используют тестовые данные.

Для создания устанавливаемого архива:

```sh
python3 scripts/package.py
```

Архив появится в `dist/wordpress-quiz-0.2.6.zip`. Он содержит только плагин;
демонстрационная тема, Docker-среда и тестовая CRM в него не входят.
На другом сайте требуется WordPress 6.8+ и PHP 8.3+.
Для доставки настройте на сервере `WPQ_CRM_URL` и `WPQ_CRM_TOKEN`
через константы или переменные окружения. Без них заявки сохраняются с ошибкой доставки.
Произвольная CRM потребует адаптации под её API.

## Устройство и ограничения

Демонстрационная среда: WordPress 7.1.0, PHP 8.3, MariaDB 11.4, WP-CLI 2.12.0.
Фронтенд использует WordPress Interactivity API; сборка Node.js для работы сайта не нужна.
Логика находится в плагине, оформление — в отдельной блочной теме.
Тестовая CRM — Python HTTP-сервис с SQLite, серверным Bearer-токеном и защитой от дублей.

Путь данных: **браузер → REST API WordPress → база WordPress → HTTP API тестовой CRM**.
В CRM передаётся единый JSON с контактами, ID и названием квиза, версией вопросов,
текстами вопросов и выбранных ответов, временем и версией согласия.
Токен CRM не передаётся в браузер.

- Пока нет ветвлений, множественного выбора, файлов, персональных результатов и аналитики шагов.
- Доставка синхронная, с таймаутом 8 секунд. Фоновая очередь и автоматические повторы не реализованы.
- Интеграция демонстрационная: подключение реальной CRM требует сопоставления полей и проверки её API.
- Защита от спама базовая. Автоудаление по сроку хранения и инструменты экспорта/удаления
  персональных данных не реализованы; резервные копии публичного сервера не настроены.
- Мобильные сценарии проверялись эмуляцией размеров окна в браузере.
  Проверка на физических Android/iPhone и нагрузочное тестирование не проводились.
- Условия формы описывают демонстрацию с вымышленными данными и не заменяют
  документы и настройки для реального сбора персональных данных.

## Форматирование исходников

CSS-свойства записываются по одному на строке с пробелом после двоеточия.
JavaScript, PHP и HTML оформляются через Prettier; настройки находятся в
`.prettierrc.json` и `.editorconfig`. Node.js и npm нужны только для инструментов разработки:

```sh
npm ci
npm run format
npm run format:check
```
