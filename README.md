# WordPress Quiz

Переиспользуемый квиз для тестового задания WordPress / AI Developer.
Собственный плагин: редактор вопросов, блок Gutenberg и shortcode, пошаговая форма,
контакты, сохранение заявки и передача полного набора ответов в тестовую CRM.

Демонстрация: https://test-wordpress-quiz.duckdns.org

Два независимых квиза: https://test-wordpress-quiz.duckdns.org/two-quizzes/

## Запуск

Нужны Docker Compose, Python 3 и Make:

```sh
make demo
```

Откройте http://localhost:8088 и http://localhost:8088/two-quizzes/.
Админка: http://localhost:8088/wp-admin/ — русский язык.
Логин и пароль находятся в `WP_ADMIN_USER` и `WP_ADMIN_PASSWORD` локального `.env`.
Файл создаётся со случайными секретами и исключён из Git. Повторный запуск сохраняет данные.
Используйте только вымышленные контакты, например `review@example.test`.

## Как проверить

1. Пройдите квиз, вернитесь на предыдущий шаг: ответы сохраняются.
2. Отправьте форму с тестовыми контактами и согласием.
3. В админке откройте **Квизы → Заявки**: видны контакты, все вопросы и ответы, статус доставки и CRM ID.
4. На странице **Два квиза на странице** проверьте независимость двух форм.
5. В **Квизы → Добавить квиз** настройте вопросы и варианты, опубликуйте. На любой странице добавьте блок **Квиз** и выберите запись либо вставьте `[wordpress_quiz id="ID"]`.

```sh
make lint
python3 tests/integration.py
python3 scripts/package.py
make down
```

Интеграционный тест временно останавливает локальную CRM и затем восстанавливает её.
Архив устанавливаемого плагина появится в `dist/`. `make down` сохраняет volumes;
`docker compose down -v` удалит данные — не используйте для обычной остановки.

## Устройство

WordPress 7.1.0, PHP 8.3, MariaDB 11.4, WP-CLI 2.12.0.
Фронтенд использует WordPress Interactivity API; сборка Node.js не требуется.
Лёгкая блочная тема отвечает за демонстрационные страницы, логика квиза остаётся в плагине.
CRM — отдельный Python HTTP-приёмник с SQLite и идемпотентностью.

- [Архитектура, редактор и ограничения](docs/architecture.md)
- [Результаты проверок](docs/verification.md)

Практическая часть реализована. Аудит двух страниц и письменные ответы по остальным пунктам ТЗ ещё готовятся.
Это демонстрация с тестовыми данными: условия формы не заменяют согласованные юридические документы.

## Форматирование исходников

CSS-свойства записываются по одному на строке с пробелом после двоеточия.
JavaScript, PHP и HTML оформляются через Prettier; настройки находятся в
`.prettierrc.json` и `.editorconfig`. Для работы сайта Node.js не нужен,
он используется только для инструментов разработки:

```sh
npm ci
npm run format
npm run format:check
```
