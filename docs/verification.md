# Проверка

Дата: 2026-09-17. Локальная версия плагина 0.2.0.

## Выполнено

- Docker Compose: WordPress, MariaDB и тестовая CRM healthy.
- Установка WordPress и повторный bootstrap без потери существующих данных.
- Локаль WordPress `ru_RU`; авторизованный доступ в админку и русское меню проверены.
- PHP lint плагина и bootstrap — успешно.
- Интеграционный тест `tests/integration.py`: HTTP-заявка сохранена и доставлена;
  JSON в CRM совпадает со снимком заявки в WordPress, включая тексты всех ответов.
- Повторная отправка с тем же ключом не создаёт второй записи, возвращает тот же receipt.
- Некорректные контакты, отсутствие согласия, неверные типы, подмена варианта,
  устаревшая схема и посторонний Origin отклоняются.
- При остановленной CRM заявка остаётся в WordPress. После восстановления и повтора
  доставки в CRM ровно одна запись.
- В браузере: последовательность шагов, ошибка без ответа, возврат с сохранением выбора,
  отправка синтетических контактов, экран успешного сохранения.
- Два квиза на одной странице (блок + shortcode): состояние и отправка независимы.
- Мобильный viewport 390×844: форма и контакты, отправка, отсутствие горизонтального
  переполнения. Это эмуляция ширины в браузере, не проверка на физическом телефоне.
- Во время этих сценариев ошибок/предупреждений консоли не обнаружено.

## Границы проверки

После этих сценариев добавлена собственная демонстрационная тема; её окончательная
визуальная проверка пока не завершена. Автоматическая проверка разрешений браузера
остановила повторную проверку из-за лимита использования.
Редактор вопросов загружался авторизованно; полный ручной сценарий редактирования
и публикации через интерфейс ещё требует проверки. Публичное развёртывание завершено.
Тест не покрывает нагрузку, реальные CRM, Safari/iOS и юридическое соответствие.

## Публичный сервер

- HTTPS на `test-wordpress-quiz.duckdns.org`: HTTP 200, сертификат проходит проверку клиента.
- WordPress в окружении production, локаль ru_RU, тема quiz-demo.
- WordPress, MariaDB и CRM healthy; наружу опубликован только HTTPS через Nginx.
- Публичный REST API: новая заявка HTTP 201, повтор той же заявки HTTP 200.
- Статус доставлена, одна попытка; ровно одна запись CRM, полный снимок вопросов
  и ответов совпадает с записью WordPress. Контакт синтетический: deployment@example.test.
- SMTP не настроен; восстановление пароля по email не проверено. Администратор
  использует сохранённые отдельно данные входа; отправка заявок работает через HTTP CRM.
